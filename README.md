# مدير المتجر | Store Manager

تطبيق ويب متكامل لإدارة المتاجر ونقاط البيع (POS) — يعمل بالكامل داخل المتصفح مع تخزين دائم محلي (IndexedDB)، بواجهة عربية RTL وإنجليزية LTR، ووضع داكن/فاتح.

## المزايا

| الصفحة | الوظائف |
|---|---|
| لوحة التحكم | مبيعات اليوم/الشهر، عدد الفواتير، المصروفات، تكلفة البضاعة المباعة، الربح الإجمالي وصافي الربح، قيمة المخزون بالتكلفة، ديون العملاء ومستحقات الموردين، منتجات منخفضة المخزون، أحدث الفواتير، الأكثر مبيعًا، رسم بياني للمبيعات والأرباح |

| الإعدادات | بيانات المتجر، نوع المتجر (بقالية/سمانة/سوبرماركت/ملحمة)، عنوان دفتر الدين، العملة، اللغة، الوضع، سياسة البيع السالب، بادئات الأرقام، **بنود المصروفات** (إضافة/حذف)، مهلة تنبيه الصلاحية، **مرادفات البحث** المخصّصة، **سياسة تسعير البيع** (لا تتغيّر/اسأل/تلقائي)، نسبة الهامش، تقريب السعر، بادئة البيع اليدوي، نسخ احتياطي/استيراد/مسح |

## القواعد المالية المطبقة

- **فصل الدخل عن التدفق النقدي**: التحصيل ليس دخلًا (الدخل سُجّل عند البيع)، والتحويل بين الصندوق والبنك ليس دخلًا ولا مصروفًا.
- **COGS بلقطة تاريخية**: تكلفة البضاعة المباعة تُحفظ داخل الفاتورة وقت البيع ولا تتغير بتغيّر سعر المنتج لاحقًا.
- **متوسط تكلفة مرجّح** عند استلام المشتريات: `(كمية×تكلفة سابقة + وارد×سعره) ÷ الكمية الجديدة`.
- **صافي الربح** = صافي المبيعات − COGS − المصروفات التشغيلية − الإتلافات (خسارة غير نقدية منفصلة).
- **قيمة المخزون ليست ربحًا**، وتحصيل ديون قديمة ليس إيرادًا جديدًا، والتحويل بين الصندوق والبنك ليس دخلًا.
- **دقة تكلفة الوحدة** = الكمية × تكلفة الوحدة دون تقريب وسيط `round4` للغرام/المل، ثم تقريب الناتج المالي فقط.
- **الفواتير الملغاة** لا تُحذف: تُعلَّم ملغاة، تُرجع الكميات، تُقيَّد استردادات في الصندوق، وتُستثنى من المبيعات والأرباح.
- **منع البيع المكرر**: مفتاح `clientToken` فريد في قاعدة البيانات + معاملة ذرية واحدة لكل عملية (فاتورة + مخزون + صندوق).
- **الأموال بدقة**: كل العمليات تمر عبر تمثيل السنتات مع قواعد تقريب موحدة (`src/utils/money.ts`).

## المسح الضوئي للفواتير (OCR)

- **محرّك حقيقي يعمل دون إنترنت**: `tesseract.js` بنماذج `ara` + `eng` تُقدَّم من `public/ocr/` (تُحضَّر تلقائيًا عبر `npm run prepare:ocr` قبل `dev`/`build`). لا يُرسل أي ملف إلى خدمة خارجية.
- **قابل للتطبيق على الفواتير المطبوعة فقط**: التعرّف على الكتابة اليدوية غير مدعوم، والواجهة تنص على ذلك — استخدم التصحيح اليدوي الكامل.
- **لا حفظ تلقائي**: نتيجة التعرّف تظهر كمسودة؛ لا تُعتمد الفاتورة ولا تُحدَّث أي أسعار أو كميات قبل ضغط «اعتماد».
- **الثقة المنخفضة معلَّمة**: حقول السعر/الكمية/الإجمالي ذات الثقة المنخفضة تُبرز للأمام وتتطلب مراجعة بشرية.
- **حفظ الصورة والنص دائمًا**: تُخزَّن الصورة الأصلية والنص المستخرج في IndexedDB، ويبقى أثر الفاتورة في المكتبة حتى بعد الحذف (سجل مراجعة)؛ فشل المسح لا يفقد الصورة.
- **تاريخان منفصلان**: تاريخ الإضافة (المسح) وتاريخ الفاتورة المدخل من المستند.
- **لا مطابقة عشوائية**: مطابقة الأصناف بالباركود/الاسم/الحجم مع درجة تشابه، وتُطلب موافقة المستخدم عند الالتباس. الصفوف غير المطابقة تُترك للمستخدم ولا تنشئ منتجات تلقائيًا.
- **سعر الوحدة لا يُستنتج من إجمالي السطر**: إذا كانت الكمية > 1 يُقسم الإجمالي أو يُطلب التصحيح، ولا يُؤخذ الإجمالي كسعر وحدة.

## حماية الأسعار والتكرار

- **كشف الفواتير المكررة** ببصمة (المورد + الرقم + تاريخ اليوم + الإجمالي)؛ لن تُخفض الأسعار مرتين من صورة معاد رفعها أو فاتورة قديمة.
- **حماية من التاريخ الأقدم**: إذا كان تاريخ الفاتورة أقدم من آخر تحديث لسعر المنتج، لا تُطبَّق قيمتها تلقائيًا؛ يُعرض تنبيه في المراجعة وتُسجَّل كـ«متخطاة» — القيمة الأحدث للمنتج تبقى.
- **ملخص مراجعة قبل الاعتماد**: لكل صنف «سعر أعلى / أقل / بلا تغيير / جديد» مع الكميات، وتأكيد صريح.
- **سياسة سعر البيع**: `never` لا يمسّ سعر البيع أبدًا · `ask` يقترح سعرًا وفق الهامش والتقريب ويطلب موافقة · `auto` يطبّقه تلقائيًا. تحديث سعر الشراء لا يغيّر سعر البيع خارج هذه السياسة.
- **ذرّية كاملة**: اعتماد الفاتورة + تحديث المخزون والأسعار يتم في معاملة واحدة؛ أي خطأ يُلغي كل شيء.
- **المنتجات غير الواردة لا تتغيّر**، والتصنيفات تُوحَّد بمفتاح تطبيع عربي (بلا تكرار بسبب فروق إملائية).

## التقنيات

- React 18 + TypeScript (strict) + Vite
- Tailwind CSS (فاتح/داكن via class)
- Lucide React (أيقونات) · Recharts (رسوم بيانية)
- React Router (تنقّل) · IndexedDB عبر `idb` (تخزين دائم)
- tesseract.js (OCR محلي) · pdfjs-dist (قراءة PDF)
- Vitest + fake-indexeddb + jsdom (اختبارات)

## التشغيل

```bash
npm install        # تثبيت الاعتماديات
npm run dev        # خادم التطوير على http://localhost:5173
npm run build      # بناء الإنتاج في dist/
npm run preview    # معاينة نسخة الإنتاج
npm test           # 97 اختبارًا (مالية + خدمات + واجهة)
OCR_LIVE=1 npm test # يشغّل اختبار OCR الحقيقي (tesseract على صور مولّدة)
```

## بيئة التشغيل والنشر

- لا يحتاج متغيرات بيئة — التخزين محلي في متصفح الجهاز (Local-first).
- بيانات كل مستخدم/جهاز مستقلة؛ للنسخ الاحتياطي: الإعدادات ← تصدير نسخة احتياطية (ملف JSON).

```bash
npm i -g vercel
vercel            # أو اربط المستودع من واجهة Vercel
```

- Framework Preset: **Vite** · Build Command: `npm run build` · Output Directory: `dist`
- لا يحتاج أي إعدادات إضافية (التطبيق يعتمد HashRouter ليعمل على أي مسار ثابت).

## الاختبارات

`npm test` يغطي:

1. دقة المال (جمع/طرح/ضرب/تقريب دون أخطاء فاصلة عائمة)
2. إضافة/تعديل منتج وجرد المخزون
3. بيع يخصم المخزون ويقيّد الصندوق
4. منع البيع المكرر (نفس المفتاح = نفس الفاتورة، خصم واحد)
5. منع بيع المخزون غير المتوفر (والسماح به عند التفعيل)
6. فاتورة نقدية وآجلة وجزئية
7. دفعات العميل وتحديث الرصيد وتطابق كشف الحساب
8. استلام شراء يزيد المخزون ويحدّث المتوسط المرجّح (ولو تكرر النقر)
9. إلغاء فاتورة/شراء مع عكس المخزون والحفظ التاريخي
10. المصروفات وقيودها في الصندوق
11. التحويل الداخلي بلا أثر على الربح
12. تطابق التقارير: مبيعات − COGS − مصروفات = صافي الربح
13. استمرارية البيانات بعد إعادة فتح القاعدة
14. صياغة جميع صفحات الواجهة دون أخطاء
15. سجل المبيعات اليدوي: منع التكرار، خصم المخزون الاختياري، تعديل/حذف مع سجل مراجعة، عدم ازدواج الاحتساب في التقارير
16. تحليل فواتير OCR: أرقام عربية/إنجليزية، تواريخ متعددة، إصلاح `4.25` المقروءة `425`، مطابقة الأصناف ودرجات الثقة
17. تدفق واجهة كامل: منتج ← بيع من نقطة البيع، بيع يدوي، البحث الشامل، صفحات المسح والمكتبة والأسعار
18. نسخ احتياطي واستيراد مع الصور
19. استمرارية المخزون والأسعار والفواتير بعد إعادة فتح القاعدة
20. ترقية الإصدار 3: التصنيفات السورية الـ16 واقتراح التصنيف، البحث بالأسماء البديلة والباركود، شراء كرتونة وبيع حبات، تحويل الوحدات ورفض التحويل غير المحدد، الإتلاف وتأثيره على صافي الربح، الصلاحية والتنبيهات، رصيد الزبون الافتتاحي والتحصيل، مستحقات الموردين وآخر الأسعار، ترحيل الإعدادات والنسخ الاحتياطي v3
